# Mentor update: Greek names, and the assistant keeps going

## What is new

- Recipes and web apps with Greek names get a file of their own. Before, a second one could quietly take the place of the first.
- Undoing a change that is not there, or was undone already, is answered at once, without asking for your password.
- The assistant keeps working when its engine says something in an unexpected way, instead of waiting forever.

## Why

- Recipe and web app file names kept only Latin letters, so a Greek title gave an empty name: every Greek recipe was `recipe.md` (the second one filed the first away as an old version of itself), and two Greek-named web apps of one site were one launcher (the second replaced the first). `latin()` in mentor_recipes.py now writes Greek in Latin ("Ρύθμιση ήχου" is rythmisi-ichou, "Καιρός" is kairos); a recipe title in another script gets `recipe-` and a short hash. RECIPES.md (the table, "Keeping one"), TOOLS.md ("Web apps"). Recipes and web apps already made keep their files.
- change_undo went to the password dialog first and only then found out that the id did not exist; it now reads the change's manifest first. AGENT.md.
- mentor-mcp ended on a line that was JSON but not an object (a bare number), and every tool of that engine's session with it; it now answers -32600 and goes on. TOOLS.md.
- mentor-chat stopped reading an engine's output when one event had a shape it did not expect (a null message), and the answer then never came; such an event is now passed over.
- mentor-host-link: a message from Mentor.exe it could not handle no longer ends the link (time zone, volume, Windows Hello); it is written in its log instead.

## Check at the end

- `mentor verify` says every file of Mentor's is as it was built.
- `mentor undo nope` says "There is no applied change 'nope'" and lists the changes, with no password dialog.
