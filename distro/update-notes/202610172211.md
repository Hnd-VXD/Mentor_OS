# Mentor update: more small fixes found by testing

## What is new

- A problem report now also leaves out a password written in plain words.
- When Mentor checks a recipe someone else made, it now lists every command in it, also the ones written in the middle of a sentence.
- Fewer false alarms in Mentor's logs, so the assistant does not mistake harmless lines for faults.

## Why

- Reports: `mentor_recipes.SECRETS` takes out "my password is hunter2" / "κωδικός abc123" (a word with a digit or symbol after the word password). Mentor's own harmless log lines are left out of a report's errors (`REPORT_NOISE` in mentor_tools.py). UPDATES.md, "Problem reports".
- Recipes: the rules' report read commands, files and programs only from fenced code blocks, so a recipe with its commands inline in backticks showed "Every command in it (0)". Inline code is read too now, and a plain "Made for GNOME 51, kernel 7.2" sentence counts as the recipe's setup. RECIPES.md, "How to tell that it works".
- Windows Hello: `/etc/pam.d/polkit-1` and `/etc/pam.d/sudo` have `quiet_log` on the `mentor-hello` line: with Hello off, every password prompt used to log "mentor-hello failed: exit code 1" as an error. WINDOWS.md, section 8.
- Sandbox: systemd-nspawn's note about a future default is no longer passed to you with every sandbox_run.
- The calendar server failing at each start is GNOME's without Evolution's data server, and harmless: DESKTOP.md says so now.

## Check at the end

- `mentor verify` says every file of Mentor's is as it was built.
- `grep quiet_log /etc/pam.d/sudo` shows the line.
