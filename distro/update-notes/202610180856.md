# Mentor update: no false alarm without a Windows host

## What is new

- Mentor started on its own, without the Mentor program on Windows, no longer reports the shared clipboard as broken.
- When something of Mentor's does go wrong, its self-check now names the error itself.

## Why

- The bootable-Mentor audit (docs/bootable-audit.md, row 1) found that with no launcher on a host there is no `/dev/virtio-ports/org.mentor.clipboard`: `mentor-clipboard` crashed at login, `mentor doctor` said "BROKEN the clipboard shared with the host" and "BROKEN errors of the assistant's", and mentor-watch turned that into a red card. Now `mentor-clipboard` ends quietly when the port is not there, and `mentor doctor` says "no host to share the clipboard with" instead of checking it. In Mentor.exe's VM the port is always there, so nothing changes there. DESKTOP.md, "The shared clipboard, for mending it".
- The doctor's "errors of the assistant's" took the 12th line after a traceback, which could be an unrelated journal line ("Starting Portal service…"); it now takes the traceback's own error line.

## Check at the end

- `mentor verify` says every file of Mentor's is as it was built.
- `mentor doctor` ends with "Everything of Mentor's desktop is in place."
