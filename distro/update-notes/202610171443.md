# Mentor update: a card when a program crashes, and safer system upgrades

## What is new

- When a program closes suddenly because it crashed, Mentor now tells you with a yellow card in the chat. Press "Let Mentor look", and the assistant finds out why and explains it in plain words.
- If the same program crashes again and again, you get one card a minute, not dozens.
- Full system upgrades fail less often. Mentor first refreshes the keys that check the downloads, which matters after months without use. It does not start with too little free space. And after a new kernel, it checks that the start-up files were made, before it suggests a restart.

## Why

- Crash cards: programs that crashed simply vanished, and nobody noticed. `mentor-crash-watch` (a user service, `mentor-crash-watch.service`, switched on by `mentor-enable`) follows systemd-coredump's records in the journal and leaves a yellow notice for each crash. It ignores repeats within a minute and Mentor's own helpers. FREEZES.md says how to read a crash and what to tell the user. The idea comes from Omarchy (MIT).
- Safer upgrades (`system_upgrade`, in `mentor_tools.py` and `mentor_core.py`): three guards from Omarchy's update. archlinux-keyring is refreshed first, in the same run as the upgrade, so a long-unused Mentor no longer stops on signature errors. The upgrade refuses below 10 GiB free on /, before any password is asked. A failed initramfs build after a kernel update leaves a red card, and the agent must not suggest a restart. TOOLS.md ("system_upgrade's guards"), AGENT.md and BOOT.md describe them.

## Check at the end

- `mentor verify` says every file of Mentor's is as it was built.
- `systemctl --user is-active mentor-crash-watch.service` says `active`.
- `mentor doctor` lists no broken part.
