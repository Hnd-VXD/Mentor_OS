# Mentor update: chat fixes

## What is new

Several things in the chat that could go wrong now work as they should. A question typed in the box over a program (Alt+Space) is no longer lost when you switch workspace. When the assistant's engine stops with no answer, the chat now says so instead of staying silent or looking busy for ever. A conversation opened again from History no longer sends its old text twice, and Clear chat really forgets it. Links in a suggestion's details show again, History reads past very long entries, and the chat starts even when one of its saved files is damaged.

## Why

A code review on 2026-11-14 found these; each was tried on a test Mentor with a stand-in engine:

- Ask box: a workspace switch closed the empty conversation whose box was lifted out (`go_to_workspace`); closing such a tab left the box orphaned (`on_close_page`); an unasked screenshot stayed attached when another file was, and its file was never removed (`close_ask`). ASKBAR.md, "When it is broken" 9.
- Engine output: a line that was not UTF-8 ended the turn while the engine ran on unseen (`on_line`); an engine that dies with no word now gets "The engine stopped without an answer"; a message of 128 KiB or more is refused with words.
- History: a reopened conversation's transcript went twice (`brought_back`, `handover`), Clear kept it (`clear`); an entry over 64 KiB stopped History (`read_history`).
- Details links in angle brackets or quotes broke the markup (`linkify_markup`).
- chat.json, advice.json, usage.json are written whole (`write_json`) and checked on reading (`advice_state`, `suggestions`, `usable_windows`).
- Steps cards shown again from the history fold and count no time.

All in /usr/local/bin/mentor-chat; ASSISTANT.md, "When it is broken" 5, lists them.

## Check at the end

- `mentor verify` says every file is as built.
- A message in the chat gets its answer as before.
