# Mentor update: the assistant knows the new Mentor.exe

## What is new

- The assistant knows how the newest Mentor program on Windows treats the mouse in games (only in full screen) and what to look for when Mentor seemed to crash about 8 minutes after starting.

## Why

- Mentor.exe 202610181753: on a slow or just-started Windows it gave up connecting to QEMU after 20 seconds, so nothing was connected for the whole start (no clipboard, no time zone, the game mouse could stay in use and catch the pointer, and no word that the start worked), and after 8 minutes it stopped a working Mentor and started it again. It now waits up to 5 minutes, writes a line in `vm\launcher.log` when it cannot connect, and stops a start only when it could have heard from it. The game mouse is used only while Mentor is full screen (the user's wish). WINDOWS.md, section 2; DESKTOP.md, "The game mouse".

## Check at the end

- `mentor verify` says every file of Mentor's is as it was built.
