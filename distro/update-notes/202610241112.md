# Mentor update: every start leaves a record on Windows

## What is new

If Mentor ever gets stuck while starting (a black window that says "Display output is not active"), there is now a record of how far it got. Mentor keeps it on Windows, in its own folder, and it goes into the diagnostics file. Nothing changes in how Mentor looks or works.

## Why

On 2026-10-24 one start after an update stood still for eight minutes with a black window, until the launcher stopped it and started again; nothing of it reached the journal, so its cause could not be found. New: `mentor-start-trace.service` (`/usr/local/lib/mentor/mentor-start-trace`, enabled by `mentor-enable`) writes the kernel's and systemd's messages to the launcher's virtio port `org.mentor.trace` from the very start until `/run/mentor/desktop-ok` appears. A Mentor.exe from 2026-10-24 on keeps that in `vm\start-trace.log` and copies a stalled start to `vm\stalls\`. With an older Mentor.exe the port is not there and the service does nothing. BOOT.md, "When a start stalls", says how to read one.

## Check at the end

- `mentor verify` says every file is as built.
- `systemctl is-enabled mentor-start-trace` says enabled.
- After the next start with the new Mentor.exe, `cat /sys/class/virtio-ports/*/name` lists `org.mentor.trace`, and `systemctl status mentor-start-trace` shows it ended after the desktop came up.
