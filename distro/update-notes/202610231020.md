# Mentor update: the repair screen scrolls back, and has a cursor and a pointer

## What is new

- In Repair mode you can scroll back to earlier text with the mouse wheel, or with Shift+PgUp and Shift+PgDn.
- A blinking cursor shows where you type, and the mouse pointer shows on the repair screen.
- The letters are sized for your screen, like the rest of Windows.

## Why

- The repair screen was the kernel's own console: it keeps nothing that scrolled away (the kernel took scrollback out), Mentor's kernel command line hides its cursor (`vt.global_cursor_default=0`), and it has no pointer, which QEMU's window handles differently from the desktop's.
- `/usr/local/lib/mentor/mentor-repair-console` now runs kmscon on VT 1 for a repair start, as `mentor-emergency-console` does for the emergency console: `kmscon --vt=1 --switchvt --font-size N --login -- /bin/login -f USER`, N = 16 pixels times the host's screen scaling (fw_cfg `opt/mentor/scale`). kmscon keeps 1000 lines, blinks its cursor, and shows its pointer on a cursor plane. If kmscon is missing or ends within 5 seconds, the kernel's console comes as before, now with its cursor shown.
- `/etc/profile.d/mentor-repair.sh` starts `mentor repair` for a login under kmscon too (`mentor_under_kmscon`), not only on tty1. REPAIR.md, "How the console looks" and "The console".
- If the repair screen does not come: `systemctl status mentor-repair-console` and `journalctl -b -u mentor-repair-console` (a line "kmscon could not start; the kernel's console is used" means the fallback ran).

## Check at the end

- `mentor verify` says every file of Mentor's is as it was built.
