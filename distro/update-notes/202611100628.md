# Mentor update: the chat no longer vanishes between workspaces, keys in Show Apps, disk space

## What is new

The chat no longer goes empty for a few seconds when you come back from another workspace. Typing and Escape work again in Show Apps when it is opened with the grid button on the taskbar. Room freed inside Mentor (deleted files, removed programs) is now handed back to Mentor's disk a quarter of an hour after every start, so on Windows that disk stops growing for ever.

## Why

- The chat crashed at every return from another workspace: an empty conversation's tab is closed then, a closing tab shrinks to no size, and with the frosted glass on it GTK crashed (DESKTOP.md, "Frosted glass"). The tabs no longer have the glass (`GLASS_CSS` in `/usr/local/bin/mentor-chat`).
- Dash to Panel 74 replaced the shell's key handling in Show Apps with a handler GNOME Shell 51 calls wrongly; every key there did nothing. `/etc/dconf/db/local.d/00-mentor` now sets `show-apps-override-escape=false` (DESKTOP.md, "Keys in Show Apps").
- `fstrim.timer` is switched on, with `/etc/systemd/system/fstrim.timer.d/10-mentor.conf` (15 minutes after every start, and weekly). DESKTOP.md, "Disk space". On Windows the rest is done by a Mentor.exe from 2026-11-10 on, which keeps itself up to date: WINDOWS.md, section 12 (cards when the Windows drive runs low, a pause instead of a broken disk when it is full, "Free up space…").

If the user says the tabs look different: they are a plain dark tint now, on purpose.

## Steps

Let the restart this update asks for happen: the chat and the timer start anew with it.

## Check at the end

- `mentor verify` says every file is as built.
- `systemctl is-enabled fstrim.timer` says `enabled`.
- `gsettings get org.gnome.shell.extensions.dash-to-panel show-apps-override-escape` says `false`.
- `grep -c 'tabbar.agent-tabs tab, dropdown' /usr/local/bin/mentor-chat` says `0`.
