# Mentor update: smaller fixes (Settings, recipes, repair console, volume keys)

## What is new

A handful of smaller things work better. Mentor Settings opens again on very large screen zoom. The recipe check reads "Needs" lines with "and" in them, is not fooled by look-alike web addresses, sees a download-and-run command split over two lines, and no longer changes the word "admin" in recipes you save. The repair console stays open when you press Ctrl+C. Volume keys that stopped working after Mentor was closed on Windows come back by themselves at the next login.

## Why

A code review on 2026-11-14 found these; each was tried on a test Mentor:

- Mentor Settings: at 225% zoom and more in a VM only one pointer size fits, and a slider of one step stopped the window from opening (`mentor-settings`, Size row); the safety, update and problem-report rows show their text plain (`use_markup=False`). SETTINGS.md, "When it is broken" 5a.
- Recipes (`mentor_recipes.py`): `parse_needs` (its pattern held two backspace characters for `\b`), `under`, `logical_lines`, `generalise` with `COMMON_NAMES`; the watcher (`mentor-recipe-watch`) marks a recipe done only once handed over, survives a damaged state file, and tells of a file with an unusual name instead of handing it to the agent. RECIPES.md, "When it is broken" 6.
- Repair console (`mentor_repair.py`): Ctrl+C or Ctrl+D anywhere keeps it open. REPAIR.md.
- Volume keys (`mentor-volume`, `mentor-taskbar-quiet`): given back when the helper stops, and at login by `mentor-volume restore-keys`. WINDOWS.md, "One volume".

## Check at the end

- `mentor verify` says every file is as built.
