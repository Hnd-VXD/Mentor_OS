# Mentor update: updates and undo that never leave things half done

## What is new

Updates and changes are safer. If an update or a change is cut off half way (the disk fills up, or the power goes), Mentor puts back what it had changed, and tells you. "Undo" now takes back only what Mentor itself changed: asking to install a program you already had, then undoing it, no longer removes that program. The assistant on the free models also keeps your request in mind after taking screenshots.

## Why

A code review on 2026-11-14 found these, each tried and fixed on a test Mentor:

- **A change cut off half way** (`mentor_sandbox.apply`): its record (`/var/lib/mentor/changes/ID/manifest.json`, state `applying`) is written before the first file, and each path in `progress` as it is reached. A copy that fails is put back at once (state `rolled back`); after a power cut, `mentor-boot check` puts it back at the next start (`cut_off`) and `restored.json` tells the user. The update's red card says "Nothing was changed" only when that is true, "Part of it could not be put back" otherwise (`ChangeHalfDone`). BOOT.md, UPDATES.md.
- **The download** of an update is checked before the one waiting is removed (`download`). UPDATES.md.
- **`mentor-enable`** enables the units of packages the user may have removed only when they are there (`enable_present`): one missing unit had stopped every update. UPDATES.md.
- **A start that worked** is written down before the kernel is copied to `/boot/mentor` (`confirm`): a failed copy no longer undoes the changes that worked. BOOT.md.
- **Undo** (`journal_undo`, JOURNAL in mentor_tools): a call that changed nothing has no line; `package_install` names only the packages it added. `file_restore` takes `explain`, so undoing a system file works. JOURNAL.md.
- **Long output the tools parse** is no longer cut (`raw`): large sandbox changes can be previewed and applied again, Greek setting descriptions load, `package_peek` finds files of large packages. TOOLS.md.
- **mentor-agent** (NVIDIA, Groq) drops older pictures before old turns and never cuts at a tool's picture (`trimmed`, `SHOWN`). ENGINES.md.

Nothing for the user to do. If they mention a notice that "the computer stopped while a change was being applied, so it was put back": that is `restored.json`; `change_list` shows the change with state `rolled back`. It can be done again if they still want it.

## Check at the end

- `mentor verify` says every file is as built.
- `mentor boot` says phase ok.
