# Mentor update: the last fixes from the review

## What is new

A few more things work as they should. Commands the assistant starts in the background no longer make it wait for minutes and think they failed. Switching model while the assistant is answering no longer mixes up which model the answer belongs to. A computer where you log in by hand now gets its update cards. And when your PC sleeps while Mentor is trying a change at start-up, the change is no longer undone by mistake.

## Why

A code review on 2026-11-14 found these; each was tried on a test Mentor:

- `_run` in `mentor_tools.py` (every command the tools run, `run_command` among them): output to a file, the command waited for itself in a process group of its own, killed with all it started on a time-out. TOOLS.md.
- `mentor-chat`: what an answer says of its model or sign-in applies only to the model it ran on (`run_model_index`, `same_model`). ASSISTANT.md.
- `mentor-watch`: watch.json written under a lock and merged (`remember`). SUGGESTIONS.md.
- `mentor_update.py`: with nobody logged in, it looks again in 10 minutes (`look_again_soon`, timer `mentor-update-check-again`). UPDATES.md.
- `mentor_boot.py` `deadline`: a pause of the VM does not count against the trial start's three minutes. BOOT.md.

## Check at the end

- `mentor verify` says every file is as built.
