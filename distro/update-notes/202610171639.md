# Mentor update: Settings no longer freezes, more languages, and the text box stays in view

## What is new

- GNOME Settings no longer freezes after you visit Mouse & Touchpad and move to another page.
- About 37 languages can now be chosen in Settings, System, Region & Language (German, French, Spanish, Italian and many more). After choosing one, log out and in again. Mentor's own buttons stay in English; the assistant answers in your language anyway.
- The assistant's text box could disappear after the desktop was revealed while it was over a program. It now always stays in view, until you press Esc.

## Why

- Settings: leaving the Mouse & Touchpad page (gesture videos) lost GTK's OpenGL context in the VM (`gdk_gl_context_make_current() failed`), and Settings stopped answering. It is now drawn without OpenGL (`GSK_RENDERER=cairo`), whichever way it is started: `/usr/local/bin/gnome-control-center` (a wrapper) and `/usr/local/share/dbus-1/services/org.gnome.Settings.service` (Settings is started by D-Bus from the app grid, so an `Exec` line in a desktop file is never used). DESKTOP.md, "Settings".
- Languages: GNOME's translations were installed, but only the English and Greek locales had been made, so Region & Language listed only those. `mentor-enable` now makes about 37 common locales. DESKTOP.md, "Languages".
- The text box: the shell's "reveal the desktop" minimized it along with the other windows. The assistant cannot see that on Wayland, so the box stayed "lifted" and was seen nowhere, and the desktop had no text box. The shell extension now never minimizes it (`_float`, `_floating` in `extension.js`). ASKBAR.md, item 5b.

## Steps

1. **Take away an earlier local fix for Settings, if the assistant made one.**
   - Look first: run_command `grep -l GSK_RENDERER ~/.local/share/applications/org.gnome.Settings.desktop`.
   - If it prints the file name: it is a copy of Settings' desktop file that the assistant made to draw Settings without OpenGL. This update does that for every way Settings is started, and the copy only hides later changes to GNOME's own file. Remove it: run_command `rm ~/.local/share/applications/org.gnome.Settings.desktop`. Add a line to `~/.local/share/mentor/notes.md` saying that Settings is drawn without OpenGL by Mentor itself now (DESKTOP.md, "Settings").
   - If it prints nothing: nothing to do.
   - Check: `ls ~/.local/share/applications/org.gnome.Settings.desktop` says there is no such file. If it is still there: stop, and say what you saw.

## Check at the end

- `mentor verify` says every file of Mentor's is as it was built.
- `localectl list-locales | grep -c UTF-8` says 37 or more.
- `mentor doctor` lists no broken part.
