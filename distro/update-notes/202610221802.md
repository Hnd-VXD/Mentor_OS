# Mentor update: links with icons in the answers, and "undo that" takes back everything

## What is new

- When the assistant names a file, a program, a page of Settings or a web page, the name is now a blue link with its icon in front: click it and it opens.
- "Put it back as it was" now takes back everything the assistant changed for that request, not just part of it, and never touches older things you chose yourself.
- The chat no longer shows lines like "[Image: original 3840x2160, displayed at …]" after the assistant looks at a picture.

## Why

- Links: `mentor-chat` draws an answer that holds `[name](file:///…)`, `[name](app:ID.desktop)`, `[name](settings:PAGE)` or `[name](https://…)` as an `AnswerView` (a read-only text view with each icon as a child anchor); every other answer is still a label. A click opens a picture in the preview over the chat, another file in its program, an app with `gtk-launch`, a Settings page with `gnome-control-center PAGE`, a web page with `gio open`. Nothing else is opened, and a link to something that is not there shows as its plain name. `SYSTEM_PROMPT` tells every engine how to write them. ASSISTANT.md, "Links in answers, with icons".
- Undo: the new tool `journal_undo` (mentor_tools.py; JOURNAL.md "Undoing a request") finds a request in the journal and takes back every change made for it, the last first, by each line's way back. It matches the request's words and the names of what was changed, never values; `every_match` takes back only requests of the newest match's day; a request that was itself an undo is never taken back. A model had turned off Night Light but left its schedule and location on, and called that "as it was".
- Picture notes: the Claude CLI puts a text note beside the result of reading a picture; `on_event` in mentor-chat drew it as the assistant's words. Text in the tools' answers ("user" events) is no longer drawn.
- If a link does not open: ASSISTANT.md, the links paragraph, "When a link does not open". If an undo took back too much or too little: `mentor journal` shows each line it ran, marked as taking back an earlier one.

## Check at the end

- `mentor verify` says every file of Mentor's is as it was built.
- `mentor call journal_undo '{"search": "nothing-matches-this-xyz"}'` answers "No change in the journal matches".
- `grep -c AnswerView /usr/local/bin/mentor-chat` gives a number above 0.
