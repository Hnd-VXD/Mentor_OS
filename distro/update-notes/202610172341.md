# Mentor update: quieter in the background

## What is new

- A big text file in your Downloads no longer keeps Mentor busy in the background.
- A program that crashes again and again gives one card, not a new one every minute.
- A broken connection while Mentor downloads an update no longer shows as "something is not running"; it simply tries again later.

## Why

- mentor-recipe-watch read every `.md` file in Downloads, Desktop, Documents and the home folder whole, every 3 seconds, to see whether it had become a recipe: a 300 MB Markdown file cost 6 % of a processor core and 600 MB of memory for as long as it was there. Each file is now looked at once for each size and time it has, and the form is checked before anything is hashed (a recipe is at most 400 kB). RECIPES.md.
- mentor-crash-watch waited a minute after each card, so a program crashing every 30 seconds gave a card each minute. Now no card while it keeps crashing (crashes less than a minute apart), and at most one card for a program each 10 minutes (`REPEAT`). FREEZES.md, "When a program crashes".
- mentor-update-check failed as a service when the package download broke or arrived damaged (and `http.client.IncompleteRead` was not caught at all); mentor-watch then showed "Something on the system is not running". It is now a line in the log, and the next look tries again. UPDATES.md.

## Check at the end

- `mentor verify` says every file of Mentor's is as it was built.
- `systemctl --user is-active mentor-recipe-watch mentor-crash-watch` says `active` twice.
