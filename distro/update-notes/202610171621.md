# Mentor update: no false warning after the computer sleeps

## What is new

- When your computer went to sleep while Mentor was checking for suggestions or updates, you could wake it to a yellow card saying "Something on the system is not running". Nothing was actually wrong. That card no longer comes for this.

## Why

- Windows pauses the VM while the PC sleeps, and systemd counted the pause as time spent. On 2026-10-17 a 30-minute sleep (`mentor-sentinel: stall of 1823.4 s, paused`) made a running `mentor-advisor.service` look hung: "start operation timed out", Result=timeout, and mentor-watch's card. `mentor-advisor.service`, `mentor-update-check.service` and `mentor-update-apply.service` now have `TimeoutStartSec=infinity`. Every download and command inside them keeps its own time limit. BOOT.md, "When Windows sleeps", says how to tell a sleep from a real failure. Tested by pausing the VM for 100 seconds: before, the advisor failed; now it finishes.

## Steps

1. **Clear a failure that only a sleep caused.**
   - Look first: run_command `systemctl show mentor-advisor mentor-update-check -p Id -p Result`.
   - If one says `Result=timeout`: run_root_command `systemctl reset-failed mentor-advisor mentor-update-check`. Then tell the user in one sentence: "The warning about something not running was only your computer going to sleep; it is fixed now."
   - If none says `Result=timeout`: nothing to do.
   - Check: `systemctl --failed` no longer lists them. If it still does: stop, and say what you saw.

## Check at the end

- `mentor verify` says every file of Mentor's is as it was built.
- `systemctl show mentor-advisor -p TimeoutStartUSec` says `TimeoutStartUSec=infinity`.
