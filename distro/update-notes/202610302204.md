# Mentor update: restore points before changes are more reliable

## What is new

If the link between Mentor and Windows drops for a moment just before an update or a system change, Mentor now waits a few seconds for it, so the restore point is still made.

## Why

On 2026-10-30 an update logged `no restore point: [Errno 11] Resource temporarily unavailable`: the link to Mentor.exe (`org.mentor.control`) was down, and the write failed at once. It was reproduced by cutting the link. `mentor_update._restore_point` and `mentor_tools._ask_host` now try writing for 15 seconds, and `_restore_point` stops at once if the link drops while it waits for the answer. Mentor.exe 202610302 and newer reconnects by itself. WINDOWS.md, section 2, "The control link dropped", also "Gone after an update's restart" and "Pointer held in a window".

## Check at the end

- `mentor verify` says every file is as built.
