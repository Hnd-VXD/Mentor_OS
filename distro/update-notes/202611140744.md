# Mentor update: four security holes on the root side closed

## What is new

Mentor's protections are stronger. A review found four ways a harmful program on this computer could get around them: read files only the system may read, have a change you approved land on a different file, slip past the guard on programs going online, or switch off the emergency key (Ctrl+Alt+Backspace). All four are closed. Nothing looks different and nothing needs to be done.

## Why

A code review on 2026-11-14 found these, each tried and fixed on a test Mentor:

- **The closer look** (`security_investigate`, `/usr/local/lib/mentor/mentor-investigate`): without the password it now opens only a file the one asking could read themselves (`readable_by`). Before, a flagged program swapped for a link to `/etc/shadow` had that file copied where anyone could read it. Such a file now gets size and owner only, and "Only the system can read this file … not scanned". The copies are now in `/run/mentor-investigate/looks/` (711). SECURITY.md, "A closer look at a flagged program".
- **How root writes files** (`write_file`, `restore_file`, `sandbox_apply`, undo; `mentor_core.py`, `mentor_sandbox.py`): to a new random name `.NAME.mentor-new-XXXX` made only where nothing is, in a folder opened and checked (`open_folder`, `new_file`), then renamed over the file. Before, the fixed name `PATH.mentor-new` followed a link a program put there, and an approved write could land on sudoers. A new error, "is not the folder it was a moment ago", means a folder on the way became a link: nothing was written. TOOLS.md, "How root writes a file".
- **The sandbox**: a folder it deleted or made again is skipped whole when anything protected is inside it, and refused when one of Mentor's own files in it would come back changed (`_protected`, `_not_as_it_is`).
- **The guard on programs going online** (`mentor-netguard`, `/etc/systemd/system/opensnitchd.service.d/mentor.conf`): OpenSnitch now finds the guard at `unix:///run/mentor-netguard-ui/osui.sock` (root only), not `/tmp/osui.sock`, which another program could take while the guard restarted; `-cCODE`, `-Ic CODE`, `--eval=` and the like count as code given as text (`_gives_code`), so `python3 -cCODE /usr/bin/ls` is no longer judged as `ls`; a failure on a program already judged unknown refuses it instead of letting it out. Older script rules are rewritten at the guard's start (`_tighten_old_rules`). A script started with a plain switch that shares a letter with these (bash `-e`, python `-E`) is now asked about. SECURITY.md, "Programs going online".
- **The emergency key** (`mentor-emergency-key`, `/etc/profile.d/mentor-repair.sh`): its mark is now `/run/mentor-emergency/opened`, in a folder only root can write; in `/run/mentor` a file made there first by any program stopped the key. FREEZES.md.

If the internet stops working for every program after this update: `systemctl is-active mentor-netguard opensnitchd` (both active), `ls -l /run/mentor-netguard-ui/` (osui.sock, root), `grep -o '"Address": *"[^"]*"' /etc/opensnitchd/default-config.json` (the same address); as root `systemctl restart mentor-netguard` and then `systemctl restart opensnitchd` puts them back together.

## Check at the end

- `mentor verify` says every file is as built.
- As root: `systemctl is-active mentor-netguard opensnitchd mentor-emergency-key` says active three times, and `ls -l /run/mentor-netguard-ui/osui.sock` shows a socket owned by root.
- Programs that went online before still do (a web page opens in the browser).
